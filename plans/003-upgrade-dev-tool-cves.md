## Why this matters

`pnpm audit` reports 2 critical + 11 high vulnerabilities in dev tools as of
commit `4748020`. Three packages account for all of the critical and the most
exploitable high findings:

1. **vitest ≥4.0.0 <4.1.0** (root `package.json`) — GHSA-5xrq-8626-4rwp,
   critical: when the Vitest UI server is listening, arbitrary files can be
   read and executed. Patched in `>=4.1.0`. Installed: `4.0.18`.

2. **vitest <3.2.6** (mcp `package.json`) — same CVE, different version
   line. Installed: `3.2.4`. Patched in `>=3.2.6`.

3. **vite >=6.0.0 <=6.4.1** (root `package.json`) — high: arbitrary file
   read via the Vite dev-server WebSocket. Patched in `>=6.4.2`. Installed:
   `6.4.1`.

4. **rollup >=4.0.0 <4.59.0** (transitive via vite) — high: arbitrary file
   write via path traversal. Installed: `4.58.0`. Patched in `>=4.59.0`.
   Bumping vite to `>=6.4.2` will pull in rollup `4.59.0+`.

All four are dev-server / test-runner surface vectors. They do not affect the
production Tauri bundle or the MCP server binary. The risk is real only when
`pnpm test --ui`, `pnpm tauri dev`, or `pnpm dev` is running on a machine that
exposes those ports — but defense-in-depth means staying current.
